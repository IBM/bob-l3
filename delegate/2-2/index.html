    MODULE 2 | DELEGATE

    APPLYING AGENTIC MODES

    i. Why this matters

    Follow the video for a full walkthrough of this scenario: Chapter 2.3: The Agentic Sidebar [IBM Bob L3]

    It's now time to apply the full Plan → review → new conversation → Code workflow towards a set of Galaxium Travels features that cut across the frontend, the backend, and the database of the application. A truly comprehensive cross-section of the application architecture will need to be modified — and thankfully, IBM Bob is up to the challenge.

    You are going to give Galaxium Travels end-users three tiers of seating options to select from with booking their extraplanetary tours: Economy, Business, and Galaxium class. Throughout this process, take note of two things: first, the increased weighting placed on IBM Bob for execution of the requested tasks; and second, the heightened importance for the user (you) in understanding and reviewing the plan of action that Bob's agentic AI processes will act upon.

    AI MATURITY CURVE

    This mirrors where you are along your journeing in shifting right along the AI Maturity Curve. By the Delegate phase, your trust in the capacity of these AI systems to carry out work as asked will have increased from the nascent Assist entrypoint. Nevertheless, human-in-the-loop review and unambiguous execution plans remain of paramount importance as planned jobs become more automated (and sophisticated.)

    ii. Hands-on: Implementing seat classes in Galaxium Travels

    1. As discussed already, the agentic sidebar is Bob's most capable interface: the place it can read files, reason across the whole codebase, ask clarifying questions, and implement a new feature end-to-end.

      You will use multiple modes when creating new features in the Galaxium Travels application. Each mode is designed for a specific phase of development. Let's put it to work adding seat classes to Galaxium Travels.

      • Begin, as always, by planning: letting Bob draft the implementation plan with us before any code is written.
      • Near the bottom of the agentic sidebar, expand the mode pop-up by pressing the blue Code button.

    1. Bob's modes tailor its level (and forms of) assistance to the task at hand: planning, implementing, debugging, or learning.

      Click on Plan from the selected of Modes inside the agentic sidebar panel.

    1. The IDE will automatically engage Plan mode, which can be confirmed by inspecting the bottom of the screen. For the convenience of the hands-on demo, let's enable auto-approval so that not every interaction you have with Bob from this point onwards needs to be manually approved in order to proceed.

      • Click the greyed-out selection box next to "Auto-approval disabled"
      • A window will appear listing all the actions that you can allow (or deny) Bob from performing autonomously

      If you prefer to still manually approve or deny actions, or if you are uncomfortable with enabling auto-approval on your device, you can leave all Auto-approval options set to the default disabled value and proceed to Step 5 at this time.

    1. For now, allow every action to be executed by Bob automatically by toggling on (checking) all available options within the panel.

      For real-world projects, set auto-approval deliberately, according to how much control you're willing to delegate directly over to Bob.

    1. With Plan mode active and auto-approval enabled, type the following task into the agentic sidebar chat window:

      I want different classes of seats for Galaxium Travels.
There is supposed to be an Economy class, a Business class, and a Galaxium class.
Help me make a plan to implement this.

    1. With the prompt entered, press Send message (the purple button with the arrow).

    1. Bob will now undertake the job of planning how to implement the requested features. It may ask follow-up questions to pin down exactly what you want.

      In this example, Bob wants to better understand how pricing according to seat classes should be structured.

      Bob's responses are non-deterministic, so questions posed to you within your Bob IDE may differ from those shown here. It's also possible you may receive no clarifying questions at all.

    1. Choose the pricing approach you want for the seat classes. In this case, recommend the following: 
      Each class has different pricing (Economy = base, Business = 1.5x, Galaxium = 2.5x) and separate seat counts per class.

    1. Inspect and review the plans that Bob creates based on your requested workflow. Bob can generate one or more Markdown (.md) plan files, with various potential names that will be specific to your project.

      For example, Bob might generate Markdown files such as SEAT_CLASSES_IMPLEMENTATION_PLAN.md, implementation-checklist.md, seat-classes-architecture.md, or seat-classes-implementation-plan.md.

      • Open (double-click) each of generated plan .md files and review them before implementation
      • If you don't see these files generated yet, continue answering Bob's questions in the Agentic Sidebar until you Bob has sufficient context to generate the requested .md files for the execution plan

      Once the implementation plan document(s) appear, the Plan mode phase is essentially complete. Bob might pose a final question to you— essentially "Are you happy with these results, or do you wish to revise things further?" —to which you may answer (if you agree):

      The plan looks great.
Let's switch to Code mode and start implementing the seat classes.

    1. Bob will wrap up the Plan mode workflow and generate a planning document. In the documented example here, that resulted in the creation of a SEAT_CLASSES_IMPLEMENTATION_PLAN.md artifact.

      Your file name will likely be different. IBM Bob may also generate additional files. Look for a file that has "implementation" in the file name.

      • Using the File Explorer tab on the left side of the interface, open (double-click) the Markdown (.md) file for deeper inspection of its contents
      • Review what you and Bob have together planned for implementation of your requested application features
      • Bob will have detailed the prices and amenities for the fictional seat classes that are to be added to the Galaxium Travels application

    1. Start a fresh conversation to clear the context window by clicking the New Task icon (the plus icon near the top of the agentic sidebar.)

    1. Click the Mode button again.

      In the documented screenshot below, the project has already engaged Code mode (Bob automatically switched it for us after concluding the Plan mode phase).

    1. Before Bob begins making alterations to the Galaxium Travels application, close any Terminal window(s) still running the demo app from Module 1 (Assist).

      While not strictly necessary, terminating earlier instances of the app will reduce the chance of Bob hitting errors while implementing your requested plan.

    1. Click the Code mode button to confirm that the Bob IDE has indeed activated the appropriate mode.

    1. In the Chat window, type the following:

      Build this feature based on @

    1. As soon as you type @, a pop-up window will appear. Click Add File.

    1. Scroll the down list of files and find the implementation plan that was generated in Step 9.

      • Upon locating the .md file, double-click to select it
      • In the documented case below, a file called SEAT_CLASSES_IMPLEMENTATION_PLAN.md was selected

    1. Notice that @/SEAT_CLASSES_IMPLEMENTATION_PLAN now appears in the chat window with a grey highlight. Bob is treating it as a file reference rather than plain text, which indicates to you that Bob knows exactly what you're pointing it at (an implementation file, specifically.)

    1. With the prompt now complete, click the purple arrow button (Send message).

    1. Bob will immediately get to work. It will first construct for itself a Todo List in order to track execution of the implementation plan.

    1. As ever, the non-deterministic workflow means your run may differ from the documented lab guide. In the example below, Bob hit an error. To showcase how you might work through a similar close:

      • Note that Bob begins debugging on its own (in this case, asking first for permission to do so)
      • Should you encounter an error or debugging question yourself, simply press Run to continue

    1. Carry on within the agentic sidebar, pressing Run when prompted to do so.

      • If Bob hits an error, it will likely diagnose (and potentially even fix) the error on its own

    1. On rare occasions, Bob may get stuck running a command. If that happens, wait a minute and then press the X inside the octagon (as shown) to invoke the Abort command.

      • After aborting the command execution, Bob should resume the workflow automatically
      • If Bob refuss to automatically restart the workflow, simply send a prompt such as the following within the chat interface: 
        Your work was interrupted, please proceed.

    1. Continue pressing Run until Bob has completed the workflow. When ready, Bob will return a similar message to the one documented below.

      • Once a confirmation of the plan's full execution has been returned to the chat interface, you will want to restart the application
      • Open a new Terminal window

    1. Close all the previously open Terminal windows (such as those from Module 1, if you hadn't previously terminated those.)

      Depending on your operating system, closing those tabs may warn you that a process will be terminated.

      Such warnings are expected and can be safely ignored.

    1. The commands to be issued to the Terminal console depending on the operating system your machine is running upon.

      From the expandable options below, follow and execute the instructions aligned to your machine's OS (either Mac/Linux or Windows). After completing the instructions within the appropriate tab, proceed to the next step in the lab guide.

      MAC OR LINUX

      On macOS or Linux, run the following commands one at a time.

      Step 1: 

      cd \~/galaxium-travels

      Step 2: 

      ./start.sh

      You should see a "Galaxium Travels is running!" prompt returned to the console (amongst other messages) once the application has deployed successfully.


      WINDOWS OS

      On Windows, run the following commands one at a time.

      Step 1: 

      cd $HOME\galaxium-travels

      Step 2: 

      cd booking_system_backend

      Step 3: 

      python -m venv .venv

      Step 4: 

      .venv\Scripts\activate

      Step 5: 

      python server.py

      DO NOT CLOSE THE TERMINAL WINDOW

      For the following Steps 6-9, you will be required to open a second Terminal window. Do not close the Terminal previously used for Steps 1-5. This window will need to remain open and active for the duration of the lab.

      Step 6: After having completed all of Steps 1-5, open a new Terminal window by pressing the Plus button.

      Step 7: Within the new Terminal window, execute the following commands one-by-one in sequence:

      cd $HOME\galaxium-travels

      Step 8: 

      cd booking_system_frontend

      Step 9: 

      npm run dev

      You should see a "Galaxium Travels is running!" prompt returned to the console (amongst other messages) once the application has deployed successfully.

    1. Open a web browser on your local machine and visit the following URL to access the Galaxium Travels application:

      WEB BROWSER

      http://localhost:5173/

    1. On the Galaxium Travels page, click Flights.

    1. Notice that each flight now shows Seat Counts for the respective Seating Class.

      To test further, click the Book Now button under any listed flight.

    1. Let's further test out the process of creating a new account.

      Click the "Don't have an account? Register" button to continue.

    1. Register for a new account using placeholder details. For example, under Name input IBM Bob and for Email input test@email.com, or other variables of your choosing. It should work so long as it respects the valid email address formatting rule that Bob generated in Module 1.

    1. The seat class selector is now in place and Bob has styled it to match the rest of the application. To test, try picking any seat class from the options presented. Note that your version may differ slightly in terms of pricing numbers and so on.

    1. With a seat selected, press the confirmation button. For example, this might be a "Confirm Booking" button or something similar. Your results may vary.

    1. Once the booking is placed, a new tab will appear at the top of the website. In the documented case here, it reads "My Bookings". Click to drill down into more details.

    1. A summary should render with details about the booked flight and— most critically —new key details on seat class, pricing, location, and dates.
