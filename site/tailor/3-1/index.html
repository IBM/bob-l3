    MODULE 3 | TAILOR

    /INIT AND AGENTS.MD

    i. Teaching Bob your codebase

    Across the first two modules (Assist and Delegate), Bob was put to work with minimal-to-no background or context about your codebase. Bob proved itself to be capable, but operating and working only from what it could read and infer based in the moment. Module 3 (Tailor) will change that approach markedly. Here you will teach Bob about your project and your standards, so that Bob begins behaving like a teammate who already knows how your team works.

    There are three ways to tailor Bob which build on one another:

    1. Provide Bob with durable knowledge about your codebase (so it stops rediscovering your project from scratch with every invocation)
    2. Encode the standards Bob must always follow (so quality and conventions are enforced without needing to be re-typed)
    3. Shape Bob's behavior to fit each role on your team (so a product manager and a senior engineer each get the specialized version of Bob that they need).

    AI MATURITY CURVE

    Notice where control lives at this stage in the AI Maturity Curve. Whereas in Modules 1 and 2 you approved Bob's work as it happened, here in Module 3 you write the rules down— commit them to the repository —and have them applied automatically, every time, for everyone. Viewed another way: Bob, at this stage in your jouney, has progressed beyond delegated work towards tailored work. Bob's behaviors, capabilities, and understanding are now being attuned specifically to the workflow and personas engaging with it.

    ii. Why this matters

    Watch first: Chapter 3.1: init Command [IBM Bob L3]

    Maximilian Jesch (Outbound Product Manager — IBM Bob) shows how Bob's init command summarizes a large, complex codebase. [2 min]

    Large language models (LLM) are stateless and therefore every new conversation, without intervening strategies or techniques, will begin with no memory of the last interaction. Left to its own devices, Bob would need to rediscover your codebase from scratch at the start of each interaction — an inefficient approach for a small project and an impractically cumbersome approach for a large one.

    The /init command solves this challenge. It scans your project and generates a structured summary that Bob loads as persistent context for every new conversation. The /init command thus becomes the primary mechanism for giving Bob durable knowledge of your project's structure, conventions, and code. All without needing to re-read every file with each new invocation.

    RUNNING /init

    Initializing a project's context takes seconds and requires no additional configuration. To do so using IBM Bob:

    1. Open the agentic sidebar in Bob IDE
    2. Enter the slash command: /init
    3. Bob reads the relevant files in the project
    4. Bob generates the agents.md context file

    You'll have plenty of opportunities to practice this yourself when the hands-on portion of Module 3 kicks off. Beforehand, however, it's important to understand more about the complementary agents.md file.

    THE AGENTS.MD FILE

    The primary output of the /init command is agents.md: a plain-text Markdown file placed in the project root directory.

    Think of agents.md as onboarding documentation written for specifically for Bob. It provides a concise, actionable summary of everything Bob needs to understand about the project in order to work effectively with it. The documentation typically covers: the project's overview and purpose; its directory structure and key file locations; the technology stack and dependencies; architectural patterns and conventions; and development workflows.

    From the point it is first introduced and defined, agents.md is automatically prepended to every new conversation a user has with Bob, ensuring the LLM has immediate project context without requiring any manual file read efforts.

    MODE-SPECIFIC CONTEXT FILES

    Alongside the main agents.md Markdown documentation, the /init command also generates context files tuned to each one of Bob's built-in Modes (which we examined in Module 2):

    FILE MODE
    .bob/agents.md All conversations (global project context)
    .bob/agents-code.md Code mode
    .bob/agents-plan.md Plan mode
    .bob/agents-ask.md Ask mode
    .bob/agents-advanced.md Advanced mode

    Each mode-specific file extends the base context with what matters most for the successful operations of a given Mode. Context for Plan mode might emphasize architectural conventions, while Code mode context would benefit from highlighting file structure and naming patterns.

    iii. Hands-on: generating your project context

    Follow the video for a full walkthrough: Chapter 3.1: init Command [IBM Bob L3]

    The larger your codebase, the more valuable a well-maintained agents.md asset becomes. On a small project, Bob could conceivably read every file each conversation; even so, having a pre-defined agents.md is still more efficient than the read-everything alternative. On a large project, an agents.md manifest becomes the backbone of the entire workflow. It provides detailed guidance for how Bob should navigate the codebase, without exhausting the context window on file reads.

    TIPS FOR /INIT AND AGENTS.MD

    Execute the /init command after significant changes to ensure Bob picks up on any new modules or services, restructured directory trees, new framework, and so on. If there are instances where you (the administrator) want to capture context without performing an automated scan— or believe that an automated scan might miss some key elements, such as business rules or deployment conventions —then you may also edit the agents.md asset by-hand.

    Let's give Bob durable knowledge of the Galaxium Travels codebase by running the /init command and generating its agents.md files.

    1. First, ensure that Bob has enabled Code mode within the Agentic Sidebar.

    1. Within the Agentic Sidebar, type the following:

      /init

      Once you have finished typing, you will be presented with a Bob Commands window pop-up with the /init command displayed.

    1. Click Send message (the purple button with the arrow) to execute the instruction.

    1. Bob will now outline its plan of acton. Review the proposed steps, then click Approve to continue.

      If you enabled auto-approval in Module 2, this workflow may complete on its own with no further intervention required on your part.

    1. As expected, a To-Do list will appear as Bob begins executing the workflow. Review the steps it proposes be undertaken and press Approve to proceed.

    1. Bob may ask you to approve commands such as mkdir, which is necessary in order to create the directories its agents.md file will require.

      Press the blue Run button to grant such permissions and carry on with the workflow.

    1. Likewise, as Bob creates or edits the protected agents.md and related configuration files, you may be asked for further approvals. Press the blue Approve button if prompted to do so.

    1. Once Bob has completed the requested workflow, you'll be presented with an "All tasks completed!" message within the agentic sidebar along with several newly-created files:

      The /init command successfully created a main AGENTS.md file in the project root and mode-specific files in .bob.

    iv. Key takeaways

    • LLMs are stateless by default: every conversation starts fresh, with no memory of the last session or chat
    • The /init command scans your project(s) and generates agents.md documentation, a context file that will subsequently be included with every new Bob conversation
    • agents.md functions like onboarding documentation: a structured summary that Bob utilizes to navigate your project(s)
    • Mode-specific agents.md files give targeted context for IBM Bob's Code, Plan, Ask, and Advanced modes
    • For large-scale projects, agents.md is essential: Bob cannot feasibly read every file at the start of each conversation without exhausting its (sizeable) context window
    • Re-run the /init command after major changes to capture the latest context for project(s)
