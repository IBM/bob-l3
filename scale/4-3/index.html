    EXTENDING WITH MCP

    i. Connecting everything back to Bob

    Why this matters

    A partner that can only touch files and run terminal commands is powerful, but it is still an island. The Model Context Protocol (MCP) is what connects Bob to the rest of your world — a standardized interface that lets LLM-powered applications reach external tools, services, and data sources through one consistent integration layer. Add MCP servers to Bob, and its reach extends to any external service that provides one. This is the final move in scaling Bob across an enterprise: making it a participant in the systems your teams already use.

    THE FULL JOURNEY ALONG THE AI MATURITY CURVE

    This final module completes your journey along the AI Maturity Curve. Before continuing on, step back and look at the shape of what you've done: - You began with Bob finishing your lines and predicting your next edit (Module 1 | Assist) - You handed Bob whole features to build from an approved plan (Module 2 | Delegate) - You taught Bob about your project structure and your organization's standards, reinforcing that learning until Bob behaved like a teammate (Module 3 | Tailor) - Finally, you made Made reliable at scale and connected to the systems your enterprise already runs (Module 4 | Scale & Extend)

    A common thread across all of these modules and discussions has been the core value that the developer stays in control. Only the stakes changed (and escalated) across the journey from the nascent phases to the right-most portions of the curve. At Assist, control was apparent — the user (you) accepting each suggestion in sequence with a high degree of oversight. At Delegate, it was approving the plans that Bob put in place and trusting it to carry on the work beyond that point. At Tailor, it was encoding the rules and committing them to repositories that would ensure Bob adhered to your coding and organizational standards.     What MCP is

    MCP defines a standard interface for connecting LLM applications to external systems. Before it existed, wiring an LLM to an external tool meant building a custom connection layer for each one — a significant, inconsistent effort that varied across teams and organizations. MCP replaces that with a single protocol both sides implement: once a service offers an MCP server, any MCP-compatible client (Bob included) can connect to it immediately, with no custom integration work.

    A coordination innovation, not just a technical one

    MCP originated at Anthropic and has since been transferred to the Linux Foundation, making it a vendor-neutral, openly governed standard — and that governance is what accelerated its adoption. Most major external services and developer tools now ship MCP servers, creating an extensive ecosystem of ready-to-use integrations.

    MCP's real impact isn't primarily technical — it's a coordination innovation. A shared standard eliminated duplicated integration effort across the whole industry.

    Adding an MCP server

    MCP servers are configured in Bob's settings through a JSON configuration file. The flow is: open Bob settings via the three-dot menu (⋯), navigate to MCP Servers, add the server configuration in JSON, and supply credentials as required. Most services publish their configuration snippet in their official documentation — and Bob itself can insert the JSON for you, handling indentation and brackets automatically.

    How you handle credentials is a governance decision in itself:

    Method Description Best for
    Inline in config Personal access token written directly in the JSON file Quick setup, local development only
    Environment variable Token stored as an OS environment variable, referenced in config Cleaner setup, avoids token in config file
    Context Forage Open-source MCP gateway for managing complex, multi-server setups Teams, production environments, multiple credentials

    Using MCP tools

    MCP tools are available only in Advanced mode. With Advanced mode active, Bob automatically recognizes the tools exposed by every configured server and invokes them in response to natural-language requests — no special syntax required. Bob simply decides which MCP tools to call based on the task you describe.

    An example: the GitHub MCP server

    The GitHub MCP server shows how much a single integration can add. Configure it — paste GitHub's configuration snippet into the JSON config, then add a personal access token whose permissions match the operations Bob will perform (reading issues, creating commits, adding comments, closing issues) — and with Advanced mode active, Bob can list and read issues, create commits and push changes, add comments, close issues, and link commits to issues. A token with insufficient permissions will simply cause the affected operation to fail, and Bob will report the permission error so you can update the token.

    Strung together, those capabilities make a complete issue-resolution loop possible entirely through natural language: ask Bob to list open issues (it calls the GitHub MCP tool to retrieve them), describe the one to fix (Bob reads the relevant code and implements the change), instruct it to commit and push (it calls the right MCP tools and git commands), then have it comment on the issue with a link to the commit and close it. A full development cycle — from issue to closed resolution — without ever leaving the Bob interface.

    And GitHub is just one server in a fast-growing ecosystem that already spans version-control and code-review platforms, project-management and issue-tracking tools, databases and data services, cloud-infrastructure providers, and internal enterprise systems. In practice, most of the external integrations a development team relies on can be connected to Bob through MCP, with no custom development.

    Key takeaways

    • MCP (Model Context Protocol) is a standardized interface for connecting Bob to external tools and services.
    • It originated at Anthropic and is now governed by the Linux Foundation as a vendor-neutral standard.
    • Its primary value is coordination: a shared standard eliminates custom integration work.
    • MCP servers are configured in Bob's settings as JSON; credentials can be inline, environment variables, or managed through Context Forage.
    • MCP tools require Advanced mode to access.
    • The GitHub MCP server lets Bob list issues, create commits, push changes, add comments, and close issues through natural language.
    • The MCP ecosystem is broad — most major external services provide MCP servers.

Run these workflows against a codebase you actually know, in front of the kind of client you actually serve, and let the maturity curve give your demonstration its spine. Bob earns trust one stage at a time — and now you can show a client exactly how.
